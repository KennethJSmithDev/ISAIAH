# ChatGPT plan connection (local Windows candidate)

This optional candidate uses the official Sign in with ChatGPT authorization flow. With an eligible account and explicit consent, the local bridge sends the selected synthetic task, messages and tool results to OpenAI. Sign-in alone does not grant plan usage. This feature does not read a user's ChatGPT conversations. The native AI Hub agent, scoped evidence tool, independent verifier and approval boundaries remain in place.

The account and bridge run on the operator's Windows host, separately from IRIS. Account tokens are protected with Windows DPAPI for the current Windows user; the browser page and IRIS never receive them. The bridge has a separate local bearer secret. The process binds `127.0.0.1`, and the existing ISAIAH gateway still requires its own active run, gateway credential, model, and budget. This is an experimental local Windows connection, not a hosted or multi-user service. Only one saved account registration is supported in this candidate.

## Connect and select a model

1. Install this package's pinned dependencies with `npm ci` in the project. Run the existing `docker/prepare.ps1 -Standalone` and follow the main README to obtain the authorized Health image and the local IPM installer. Keep the resulting `.local` files private.
2. Set `ISAIAH_CHATGPT_ACCOUNT_DIR` to a private local directory for the account store, then run `node chatgpt/account-cli.mjs login`. Complete the OpenAI browser authorization and grant ChatGPT plan usage. `node chatgpt/account-cli.mjs status` shows whether the grant is enabled; `node chatgpt/account-cli.mjs models` lists account-visible model IDs. Do not paste tokens into the application.
3. Generate a separate random 64-character uppercase hexadecimal bridge credential and save it in `.local/provider-credential.txt`, protected as an operator secret. Do not reuse the IRIS, trace, or ISAIAH gateway credentials. Select a model from the returned catalog; catalog presence alone does not prove a successful inference request.
4. Place a private `.local/provider-profile.json` with `id` `chatgpt-plan`, `kind` `openai-compatible`, the selected `model`, and `origin` `http://host.docker.internal:18759` when the app runs in Compose. For a host-local app, use `http://127.0.0.1:18759`. Use the explicit local provider and provider-auth Compose overlays described in `provider-profiles.md`.
5. On the Windows host set `ISAIAH_CHATGPT_ACCOUNT_DIR`, `ISAIAH_CHATGPT_BRIDGE_SECRET_FILE` (the credential file's absolute path), and `ISAIAH_CHATGPT_MODEL` to the same selected model. Run `node chatgpt/bridge.mjs`. Leave this process running while ISAIAH uses the profile. Start the task-owned Compose sandbox with `docker/compose.provider.yaml` and `docker/compose.provider-auth.yaml` in addition to its normal overlays.

When this profile is selected, the workspace links to the local account page at `http://127.0.0.1:18759/`. It displays connection and plan-grant status, can open the consent flow, and can disconnect. Changing the selected model currently requires restarting the bridge and application. Sign-out attempts remote token revocation and clears the local tokens; if revocation cannot be confirmed, check ChatGPT settings. A registration identifier remains encrypted so reconnect can use the same registration.

Normal bridge shutdown releases the account lock. If a process is forcibly terminated, a stale `account.lock` may remain. Verify the PID in that file has exited before removing that exact lock file. Do not delete the protected account record or another running process's lock. Switching accounts, other operating systems, and hosted use are not qualified.

## Compatibility and verification

The bridge converts the bounded AI Hub Chat Completions request into a streamed, non-stored Responses request, preserves scoped function-call identity and returned reasoning items across tool turns, and accepts success only on `response.completed`. Unsupported message and tool shapes fail closed. A successful catalog lookup or sign-in alone is not native-agent qualification.

The locally qualified synthetic route used `gpt-6.1-sol` and the Codex model `gpt-6.1-terra` with IRIS for Health Build 154U. With each model, both R17 and R29 exercised native AI Hub, the scoped evidence tool and the independent verifier. Results for another account, model, provider, or real production are not established by those tests. The ChatGPT Responses plan route is a preview with feature, eligibility, account and usage limitations; consult [OpenAI's plan-use documentation](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).
